## 2. Filter 정의

필터는 `src/config/filters.json` 에서 관리하며, 코드 수정 없이 조건을 변경할 수 있습니다.

### 2.1 지원 연산자

| 연산자 | GA4 FilterExpression |
|---|---|
| `contains` | `stringFilter.matchType = CONTAINS` |
| `not_contains` | `notExpression(stringFilter CONTAINS)` |
| `exact` | `stringFilter.matchType = EXACT` |
| `not_exact` | `notExpression(stringFilter EXACT)` |
| `begins_with` / `ends_with` | `BEGINS_WITH` / `ENDS_WITH` |
| `regex` | `stringFilter.matchType = FULL_REGEXP` |
| `not_regex` | `notExpression(stringFilter FULL_REGEXP)` |
| `in_list` | `inListFilter` |
| `not_in_list` | `notExpression(inListFilter)` |

조건이 2개 이상이면 `andGroup` 으로 묶습니다.

### 2.2 항목별 필터

| 분석 항목 | 필터 조건 |
|---|---|
| 페이지 경로 | 없음 |
| 자연 유입 | `sessionCampaignName` 에 `(` 포함 **AND** `sessionSourceMedium` 에 `cpc` 미포함 |
| 캠페인 유입 | `sessionManualCampaignName` 에 `(` 미포함 |
| 맞춤 이벤트 | `eventName` 제외 목록(7건) **AND** 자동수집 이벤트 정규식 불일치 항목만 |
| 성연령 | `userGender ≠ unknown` **AND** `userAgeBracket ≠ unknown` |
| 기기 | 없음 |
| 지역 | 없음 (필요 시 `region ≠ (not set)` 조건을 추가하도록 예시 주석 포함) |

**맞춤 이벤트 제외 목록**

```
page_view, session_start, scroll, click, user_engagement, first_visit, screen_view
```

**맞춤 이벤트 제외 정규식** (`filters.json > custom_event`)

```
^(form_start|form_submit|file_download|video_(start|progress|complete)|view_search_results|
session_end|app_(remove|update|clear_data|exception)|os_update|firebase_.*|notification_.*|
dynamic_link_.*|ad_(click|exposure|impression|query|reward)|in_app_purchase|screen_view)$
```

> 기획서 3.4 의 "정규 표현식은 별도 상수/설정값으로 관리" 권고를 반영했습니다.
> 운영 중인 기존 분석 기준이 있다면 이 값만 교체하면 됩니다.

> **기획서 내 상충 사항**: 기획서 본문(2.3 / 3.2)은 자연 유입 필터를 "세션 캠페인에 `(` 포함"으로,
> 8.2 예시 JSON 은 `"session_campaign": "contains:-"` 로 기술합니다.
> 본 구현은 본문 기준인 `(` 포함을 채택했습니다. 운영 기준이 `-` 라면 `filters.json` 의 값만 변경하면 됩니다.

## 3. GA4 API 조회 구조

### 3.1 Request 구조

모든 분석 항목은 `properties.runReport` (Data API v1beta) 단일 형태로 조회합니다.

```jsonc
{
  "dateRanges": [{ "startDate": "2026-08-01", "endDate": "2026-08-31" }],
  "dimensions": [{ "name": "sessionManualCampaignName" }, { "name": "sessionManualSourceMedium" }, { "name": "sessionManualAdContent" }],
  "metrics": [{ "name": "sessions" }],
  "orderBys": [{ "metric": { "metricName": "sessions" }, "desc": true }],
  "limit": 250,
  "metricAggregations": ["TOTAL"],
  "keepEmptyRows": false,
  "dimensionFilter": {
    "notExpression": {
      "filter": {
        "fieldName": "sessionManualCampaignName",
        "stringFilter": { "matchType": "CONTAINS", "value": "(", "caseSensitive": false }
      }
    }
  }
}
```

- `metricAggregations: ["TOTAL"]` → `limit` 을 초과하는 행까지 포함한 **전체 합계**를 받아 비중 계산의 분모로 사용합니다.
- 비교 기간은 `dateRanges` 를 교체한 **동일 구조의 별도 요청**으로 조회합니다.
  (분석 기간과 비교 기간의 행 집합이 달라 동일 응답 내 비교보다 매핑이 정확합니다.)

### 3.2 호출 순서

```
accountSummaries.list        계정/속성 목록
        ↓
properties.get               속성명 · 타임존
        ↓
properties.runReport × 1     권한 확인 (1행 조회)
        ↓
properties.runReport × N     7개 항목 × (분석 기간 + 비교 기간) — 동시 실행 4개 제한
```

### 3.3 Response 처리

```jsonc
{
  "rows": [
    { "dimensionValues": [{ "value": "..." }], "metricValues": [{ "value": "123" }] }
  ],
  "totals": [{ "metricValues": [{ "value": "45678" }] }],
  "rowCount": 132
}
```

→ 내부 정규화 구조

```jsonc
{
  "rows":   [{ "dimensions": ["..."], "metrics": { "sessions": 123 } }],
  "totals": { "sessions": 45678 },
  "rowCount": 132,
  "metrics": ["sessions"]
}
```

## 4. 데이터 가공 기준

`src/services/dataProcessor.js`

1. **정렬** — 첫 번째 Metric 기준 내림차순
2. **상위 N 추출** — 항목별 `topN`
3. **비중 계산** — `행 값 ÷ 전체 합계(totals) × 100`
4. **기타 행 생성** — `GA4 원본 합계 − 상위 N 합계` 를 `기타 (n건)` 으로 1행 제공
   (limit 밖 행까지 포함되며, 값이 0 이하면 행을 생성하지 않음)
5. **기간 비교** — Dimension 값 조합을 키로 현재/비교 기간 행을 매핑
   - `현재 값`, `비교 값`, `증감 수치 = 현재 − 비교`
   - `증감률 = (현재 − 비교) ÷ 비교 × 100`
   - 비교 기간 값이 **0 또는 없음** → 증감률 `null`, 표기 `신규` 또는 `-`
6. **차트 데이터 구조화**
   - 가로 막대: 상위 N 행 (1위가 위로 오도록 역순 배치)
   - 묶은 세로 막대(성연령): 카테고리 = 연령, 계열 = 성별
   - 도넛(기기): 1번째 Dimension(기기 카테고리) 기준 집계
7. **그룹 요약** — 도넛/묶은 막대 항목은 1번째 Dimension 기준 집계값을 별도 제공
8. **KPI 산출** — 슬라이드 상단 카드 4장의 값 (5.3 참조)
9. **짧은 라벨 생성** — 차트 축·문구용 축약 라벨
   (페이지 경로는 `/entry/`·`/category/` 접두사 제거, 소스/매체는 소스만, 지역은 시/군/구 우선)
10. **예외 플래그** — `lowData`(표본 과소), `footnote`(조합 합계 > 원본 합계) 판정

### 4.1 비교 기간 계산 규칙

| 선택 | 계산 |
|---|---|
| 비교 없음 | `null` |
| 직전 기간 대비 | 분석 기간과 **동일 일수**의 직전 기간. 단 `전월`/`당월` 프리셋은 직전 **달 전체** |
| 전년 동기간 대비 | 시작일·종료일에서 연도만 −1 |

기준일(`오늘`)은 **GA4 속성의 타임존** 기준으로 계산합니다.


### 5.3 KPI 카드 4장

| 순서 | 내용 |
|---|---|
| 1 | `{측정 항목} 합계` + 비교 기간 대비 증감률 |
| 2 | `{비교 기간} {측정 항목}` + 증감 수치 (비교 없으면 조회 행 수) |
| 3 | 섹션별 대표 비중 (1위 콘텐츠/유입/이벤트 비중, 성별 비중, 기기 비중 등) |
| 4 | 상위 N 집중도 또는 섹션별 보조 지표 (총 사용자, 최다 연령대, 캠페인 유입 비중 등) |

3·4번 카드는 `dataProcessor.buildSectionKpis()` 에서 섹션별로 산출합니다.

### 5.4 표 컬럼 규칙

- `No.` + Dimension 컬럼 + Metric 컬럼 + `비중` + (비교 시) `증감률`
- Dimension 이 3개 이상이면 2번째 컬럼에 나머지를 `A / B` 로 병합 표기
- 컬럼 폭은 섹션별 비율(`TABLE_HINTS`)로 배분하고, 내용은 폭에 맞춰 말줄임
- 마지막 2행: `기타 (n건)`, `합계`
- 증감률 셀은 증가(녹색) / 감소(적색) / 신규(흰색) / 비교 불가(회색)로 구분

### 5.5 예외 레이아웃

| 상황 | 레이아웃 |
|---|---|
| 데이터 0건 · 조회 실패 | 본문 전체를 `NO DATA` 패널로 대체하고 적용 필터 표기 |
| 표본 과소 (행 3개 이하 또는 합계 20 미만) | 차트 대신 비교 기간/분석 기간 수치 비교 바 + 점검 체크리스트 카드 |
| Dimension 조합 합계 > GA4 원본 합계 | 표 하단에 중복 집계 각주 표기, 집중도 문구 생략 |

## 6. 분석 문구 생성 기준

`src/services/insightGenerator.js` — **규칙 기반**이며, 조회된 수치에서만 문장을 생성합니다.
데이터에 없는 원인·해석·추정은 생성하지 않습니다. (기획서 6장)

| 순서 | 규칙 | 생성 조건 |
|---|---|---|
| 1 | 합계 및 증감 | 항상 |
| 2 | 최상위 항목 + 비중 | 행 1건 이상 |
| 3 | 상위 N 집중도 | 행 3건 이상 |
| 4 | 최대 상승 항목 | 비교 기간 값 ≥ 5 |
| 5 | 최대 하락 항목 | 비교 기간 값 ≥ 5, 상승 항목과 다를 것 |
| 6 | 신규 유입 항목 | 비교 기간에 없던 항목, 현재 값 ≥ 5 |
| 7 | 항목별 특화 문구 | 아래 표 |

**항목별 특화 문구**

| 항목 | 문구 |
|---|---|
| 페이지 경로 | 1위 페이지 비중이 50% 이상일 때 집중도 언급 |
| 자연/캠페인 유입 | 상위 유입 경로의 소스/매체 개수 |
| 맞춤 이벤트 | 1위 이벤트의 총 사용자 수 및 사용자당 평균 발생 횟수 |
| 성연령 | 성별 1위 비중 + 연령 1위 구간 |
| 기기 | 기기 카테고리 1~2위 비중 |
| 지역 | 지역(시·도) 1위 비중 |

- 중복 문장 제거 후 **최대 6문장**
- 데이터 0건 → `선택한 분석 기간에 해당 조건을 만족하는 데이터가 없습니다.` + 적용 필터 안내
- 조회 실패 → `GA4 데이터 조회에 실패했습니다. (사유)`

## 7. 예외 처리 기준

기획서 8.3 대응.

| 상황 | 처리 |
|---|---|
| 데이터 0건 | 섹션 `status = empty`. PPT 는 표/차트 대신 `데이터 없음` 박스 + 적용 필터 표시 |
| 특정 Dimension 값 없음 | 빈 문자열을 `(not set)` 으로 치환 |
| `unknown` 만 존재 | 필터 결과가 0건 → `데이터 없음` 처리와 동일 |
| 비교 기간 데이터 없음 | 증감률 `null`, 표기 `-` 또는 `신규`. 문구에 비교 불가 사유 추가 |
| 비교 기간 API 오류 | 분석 기간 데이터만으로 보고서 생성, 증감 컬럼 제외 |
| 특정 섹션 API 오류 | 해당 섹션만 `status = error`, 나머지 섹션은 정상 생성 |
| 지표 비호환 오류 | `metricFallback` 으로 1회 재시도 (예: 성연령 `sessions` → `totalUsers`) 후 대체 사실을 문구로 안내 |
| 권한 없음 | 속성 선택 시 1행 조회로 사전 검증, 화면에 사유 표시 |
| 토큰 만료 | refresh token 으로 자동 갱신, 실패 시 401 → 재로그인 유도 |

## 8. 데이터 흐름 요약

```
GA4 OAuth 로그인
   ↓  accountSummaries.list
GA4 계정/속성 조회 → 속성 선택 → properties.get (타임존) → 권한 확인
   ↓
분석 기간 / 비교 기간 계산 (속성 타임존 기준)
   ↓  runReport × (항목 수 × 기간 수), 동시 4개
GA4 원천 데이터 수집
   ↓  filters.json 조건은 API 요청에 포함되어 서버 측에서 적용
정렬 → 상위 N → 비중 → 기간 비교 → 차트 데이터
   ↓
분석 문구 생성 (규칙 기반)
   ↓
PPT 템플릿 적용 → 슬라이드 생성
   ↓
pptx 파일 다운로드
```
